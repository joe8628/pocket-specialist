## Context
The repo had `ExtractionTask`/`ProcessingUnit` contracts and checkpoint
observations, but pages were still processed in hand-written sequential loops —
the graph existed as data, not as the orchestration mechanism the spec (§4)
describes. Retries, dependency scheduling, checkpoint-aware skipping, and GPU
gating each need one shared implementation to be credible.

## Decision
A generic `DAGExecutor` in `core/` drives execution. It uses a thread pool for
runnable tasks (CPU-concurrent) plus task-declared resource semaphores so
`layout`/`ocr`/`formula` serialize while `cpu` work gets capacity equal to the
worker count. PDF flows model `layout -> structured` dependencies explicitly. It
participates in checkpoint semantics directly (`record_node_start/done/failed`,
`should_process_node`). A resume hook rehydrates a skipped node's artifact into
memory, and a `done` node is only trusted after its recorded artifact path is
validated; stale/missing artifacts force a rerun.

## Alternatives considered
- Another page-loop helper inside `phases/extract.py` — rejected: the problem is
  architectural, not phase-local; specialized loops can't give real DAG behavior.
- One global resource gate for all tasks — rejected: it silently serializes CPU
  work, turning a "DAG" back into a linear pipeline (guarded by a dedicated test).
- Trust checkpoint `done` state alone — rejected: a skipped `layout` left
  `page_state` empty and crashed `structured`; resumes were unsafe across output
  dir changes or vanished temp artifacts.

## Consequences
Skipped nodes are materially available to dependents and to `document.json`
assembly. `extract_structured_document()` counts structured tasks only (incl.
valid skipped pages). Single-page image/full-page-OCR sources stay on a direct
path for now. GPU serialization is enforced via DEC-0008, not the executor itself.
