## Context

The pending layout standardization decision (still open; currently
`pp-doclayout-v3` by [[DEC-0006]]) was about to be recorded from these numbers,
measured on page 6 of the mpphys PDF at 192 DPI:

| Provider | Regions | Formula regions | Mean confidence |
|---|---|---|---|
| PP-DocLayoutV3 | 55 | 29 | 0.81 |
| PaddleOCR service | 51 | 25 | 0.86 |
| Surya v2 service | 26 | 4 | — |

A code review of the layout path established that **these are not measurements of
the same quantity**:

- `pipeline.toml` sets `threshold = 0.5`, `formula_threshold = 0.6`,
  `img_size = 800`, which reach PP-DocLayoutV3 and PaddleOCR. The Surya provider
  sends `{"provider": name}` on `/load` and applies **no threshold anywhere** —
  its 26 is an unfiltered count against two filtered ones.
- Three independent label maps exist (`providers.py:44`, `service.py:30`,
  `paddle_service.py:36`). Surya maps `text_inline_math` and `chemicalblock` to
  `formula`; PP has no equivalent. Part of the 6–7× formula gap is a **taxonomy
  artifact**, not model behavior.
- Surya defaults a missing confidence to `1.0` (`service.py:192`), inflating its
  `layout_confidence` mean.
- PP-DocLayoutV3's own `id2label` contains duplicate names — `formula` at both id
  5 and id 15 — which `normalize_layout_label` silently collapses into one bucket.

Two comparison questions were identified, answering different things:
**controlled** ("which model is better on identical input") and **best-case**
("which model performs best as it would actually be deployed").

## Decision

Do **controlled mode first**, and make the layout standardization decision from it.

A controlled run pins every provider to one identical set of conditions:

- one shared `RenderSpec` ([[CON-0004]]), overriding each provider's declared spec
- one detection threshold, applied at one place
- one label taxonomy, applied at one place
- the operating point recorded in `summary.json` alongside the results

Best-case mode — each provider receiving its own declared `RenderSpec` per
[[DEC-0016]] — is implemented afterwards and used as a tiebreaker, not as the
primary evidence.

No layout standardization DEC may be recorded from the pre-controlled numbers
above (binding form: [[RUL-0007]]).

## Alternatives considered

- **Record the decision from the existing page-6 numbers** — rejected: the three
  numbers are produced under three different filtering and taxonomy regimes, so
  the comparison has no meaning.
- **Best-case mode first** — rejected: it conflates model quality with per-model
  tuning, and the tuning is exactly what is not yet settled.
- **Fix only the threshold asymmetry and re-run** — rejected: the divergent label
  maps would still make region-type counts incomparable, which is the specific
  signal the formula question depends on.
- **Sweep thresholds at analysis time instead of pinning one** — not rejected;
  preferred *within* controlled mode. Capturing unfiltered regions and applying
  the threshold at analysis yields precision/recall curves rather than one
  arbitrary operating point.

## Consequences

**Easier:** the decision rests on one isolated variable — the model. Capturing
regions unfiltered makes the formula-count question answerable rather than merely
observable.

**Harder:** controlled mode requires prerequisites that do not exist yet — a
per-provider `base_url` (one scalar is currently shared by the Surya and
PaddleOCR providers, so they cannot both be reached from one process), a single
shared label map, and a threshold applied in one place.

**Forecloses:** nothing permanently. Best-case mode remains planned; it is
sequenced second, not dropped.
