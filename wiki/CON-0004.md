## Definition

**RenderSpec** — the rasterization requirement a layout provider *declares* about
itself: how many pixels it wants on the page's long edge, and whether it wants
an in-process bitmap or PNG bytes for a wire transport.

```python
@dataclass(frozen=True, slots=True)
class RenderSpec:
    target_long_edge: int                  # px on the page long edge
    transport: Literal["bitmap", "png"]    # in-process vs HTTP service
    color: Literal["rgb", "gray"] = "rgb"
```

**PageRaster** — the typed carrier produced by the renderer for one page against
one RenderSpec. It holds the decoded bitmap **once** and derives every other
representation lazily and memoized.

```python
@dataclass(slots=True)
class PageRaster:
    page_num: int
    width: int; height: int; dpi: float
    _samples: bytes                     # raw, decoded exactly once
    def to_pil(self) -> Image           # ~1.1 ms
    def to_png(self) -> bytes           # memoized; encode at most once
    def crop_png(self, bbox) -> bytes   # crops the bitmap, never re-decodes
```

## Why it matters / where it appears

The spec exists because **providers do not want the same pixels**. Measured on
this repo's PP-DocLayoutV3 (`preprocessor_config.json`, verified by running the
processor):

| Render DPI | Rendered size | Tensor reaching the model |
|---|---|---|
| 144 | 1191×1684 | (1, 3, 800, 800) |
| 192 | 1588×2246 | (1, 3, 800, 800) |
| 300 | 2481×3508 | (1, 3, 800, 800) |
| 400 | 3308×4678 | (1, 3, 800, 800) |

PP-DocLayoutV3 hard-resizes to 800×800, bicubic, **non-aspect-preserving**.
Render DPI above roughly 2× the target long edge is pure waste for it and for
PaddleOCR's PP-DocLayout_plus-L. Surya v2 is a dynamic-resolution VLM and is the
one provider that genuinely benefits from more pixels.

PageRaster exists because the old `bytes` contract forced repeated PNG
encode/decode. Measured on page 6 of the mpphys PDF at 192 DPI:

| Operation | bytes contract | PageRaster | Speedup |
|---|---|---|---|
| Full-page bitmap → PIL | 59.8 ms (PNG round-trip) | 1.1 ms | 57× |
| 55 region crops | 991 ms | 18 ms | 56× |

Appears in: `render/raster.py` (owner), `layout/providers.py` (declared per
provider, consumed by `detect`), `phases/extract.py` (render + crop sites),
`layout/compare.py` (comparison harness).

## Boundaries

- A RenderSpec is **not** a model config. It describes pixels handed *to* a
  provider, not `threshold`, `img_size`, or `layout_nms`, which are the model's
  own inference parameters and stay in `LayoutSettings`.
- A PageRaster is **not** a CIF artifact and never crosses into `document.json`.
  It is transient per-page working state, replacing the untyped `page_state`
  dict — which makes it *more* RUL-0001 conformant, not less.
- `target_long_edge` is **not** DPI. DPI is derived from page geometry; the spec
  is resolution-relative so it behaves the same on A4, Letter, and slides.
- `transport: "png"` is not an accuracy choice — it is the wire format the HTTP
  service contract requires (DEC-0005). In-process providers never need it.
