## Definition
An isolated provider service is a model provider (layout: Surya, PaddleOCR;
formula: UniMERNet) that runs as a separate process with its own virtualenv under
`services/<name>/`, reached by the main runtime over HTTP at `PIPELINE_*_BASE_URL`.
Every such service exposes the same contract: `POST /load`, `POST /detect` (layout)
or `POST /extract` + `/extract_batch` (formula), `POST /offload`, `GET /health`.

## Why it matters / where it appears
It is how the system honors "provider isolation" without dependency conflicts:
the main runtime never imports `surya`, `paddlepaddle`, or UniMERNet. The repo-side
`LayoutResult` / `FormulaResult` contracts stay stable even when upstream library
objects change shape (e.g. Surya v1 → v2). Operationally, services must be started
and warmed; `/load` may be slow (Surya v2's Dockerized vLLM cold start was ~294s),
and `/offload` must actually tear down the backend (stop the `surya-vllm-<port>`
container), not just drop Python references.

## Boundaries
It is NOT the in-process PP-DocLayoutV3 provider, which runs through Transformers
inside the main runtime (DEC-0006). It is NOT the model itself — it is the process
+ HTTP boundary around a provider. `/health` reachability does not imply `/detect`
works (the PaddleOCR service was healthy but its inference path still failed).
