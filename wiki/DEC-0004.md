## Context
The reference target is a single constrained local GPU (e.g. RTX 2080 Ti). If
every model (layout, OCR, formula) is allowed to stay resident, the pipeline
OOMs or thrashes. The v0.5.1 spec (§2) makes "Explicit GPU ownership" a core
principle: models must be loaded and offloaded deterministically rather than left
to garbage-collection timing.

## Decision
GPU residency is managed at explicit lifecycle boundaries. Subsystems acquire the
GPU through the scheduler, do their work, and offload deterministically on
teardown. Cross-subsystem GPU use is serialized rather than assumed concurrent.

## Alternatives considered
- Keep all models resident — rejected: exceeds the reference card's VRAM; couples
  viability to expensive hardware the project explicitly targets away from.
- Rely on Python GC / framework caching to free VRAM — rejected: non-deterministic
  release causes intermittent OOM that surfaces far from its cause.

## Consequences
Adds explicit acquire/offload code at subsystem edges and a serialization point
(the GPU scheduler / file lock). In exchange the pipeline degrades predictably on
constrained hardware. Enforced today by the file-lock GPU scheduler and the
Phase B/C serialization; Surya vLLM offload-on-teardown is part of this contract.
