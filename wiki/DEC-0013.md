## Context
An interim adapter assigned `reading_order` by sorting detections with a
top-to-bottom, left-to-right bbox key (added to fix an earlier bug where raw
detection enumeration order leaked into CIF). Moving to the lower-level
Transformers path exposed the model's native `order_seq`.

## Decision
Rejected the geometric re-sort. The `PPDocLayoutV3LayoutProvider` now preserves
the model's native reading-order output (`order_seq`) directly. The
`AutoImageProcessor` + `AutoModelForObjectDetection` path is used specifically
because it preserves `polygon_points` and `order_seq` that the generic
`pipeline("object-detection")` path discarded.

## Alternatives considered
- Keep the bbox-key geometric sort — rejected: a pragmatic approximation that is
  strictly worse than the model's trained ordering on multi-column scientific pages.

## Consequences
Reading order now comes from the model. Also note the also-rejected generic
`transformers.pipeline("object-detection")` path, which loses polygons and order.
The metadata key `checkpoint_stage` was likewise rejected as duplicative (DEC-0010).
