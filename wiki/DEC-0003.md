## Context
A named failure mode for OCR/ingestion pipelines is "markdown-as-structure":
treating a rendered markdown document as the source of truth, then re-parsing it
to recover structure. It loses provenance, coordinates, and typing, and the loss
is silent. The v0.5.1 spec (§2 Core Architectural Principles) makes "Rendering is
not storage" a first-class principle.

## Decision
Markdown (and any other presentation format) is produced **on demand** as an
export/render of the Canonical Intermediate Format. No stage may read markdown
back in as structured state, and no stage may persist markdown as the contract it
hands to the next stage. Typed CIF (DEC-0001) is the only inter-stage state.

## Alternatives considered
- Markdown intermediates between stages — rejected: this is the exact failure the
  architecture exists to avoid; coordinates/provenance/typing are lost silently.
- Dual-write CIF + markdown as co-equal state — rejected: two sources of truth
  drift apart; markdown wins by being human-readable and then becomes load-bearing.

## Consequences
The legacy `compat/` flow (`correct` → `.md`, `assemble` → `.md`) and the
`serializers/markdown.py` path violate this and are therefore **legacy, not the
target**. They remain only for backward compatibility and are slated for removal;
new work must target `extract-structured`. The `_dev_checkpoints/*.md` dumps are
debug renders, not state, and are covered by the "remove before release" debt.
