## Rule

On any GPU with CUDA compute capability < 8.0 (Turing and older — the reference
RTX 2080 Ti is 7.5), the Surya layout service MUST be started with
`VLLM_DTYPE=float16` in its environment:

```bash
VLLM_DTYPE=float16 PYTHONPATH=src services/surya_layout_service/.venv/bin/python \
  -m pocket_specialist.layout.service --host 127.0.0.1 --port 8004
```

## Rationale

Surya v2's vLLM backend spawns `vllm/vllm-openai` with `--dtype bfloat16` by
default. vLLM refuses bfloat16 below compute capability 8.0
(`ValueError: Bfloat16 is only supported on GPUs with compute capability of at
least 8.0`). Because the container is launched with `docker run -d --rm`, the
crash is invisible: the container self-deletes, and Surya's spawner polls a
nonexistent health endpoint for the full 600 s `SURYA_INFERENCE_STARTUP_TIMEOUT`
before failing with `vllm server failed to become healthy ... No such container`.
Diagnosed 2026-07-01 during the 3-provider layout runtime verification; with the
override, observed cold start ≈ 417 s and warm detect ≈ 3.3 s on page 6 of the
mpphys corpus PDF. Relates to DEC-0004/DEC-0005 (isolated provider lifecycle).

## Exceptions

GPUs with compute capability ≥ 8.0 (Ampere+) may use the bfloat16 default.
